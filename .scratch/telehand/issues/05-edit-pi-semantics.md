# 05: `edit` 行为与 pi 一致

**What to build:** agent 能用 `edit` 在一次调用中对一个文件做多处精确文本替换，行为与 pi coding agent 完全一致：每个 `oldText` 都对原文件匹配，必须唯一且互不重叠；精确匹配失败时进行模糊匹配；保留原文件的换行风格与 BOM；各类失败给出与 pi 一致、可操作的错误信息；宽容接受旧式或被序列化的参数。受与 `write` 相同的写范围限制，并与 `write` 共享按路径串行。

**Blocked by:** 04

**Status:** done

- [x] `edit` 的参数 schema（`path` + `edits[{oldText,newText}]`）、描述与使用指引文案与 pi 一致
- [x] 宽松参数解析：接受 JSON 字符串形式的 `edits`、单个对象形式的 `edits`、旧式顶层 `oldText`/`newText`
- [x] 去除并记住 BOM，检测并恢复 CRLF/LF
- [x] 精确匹配失败时按 pi 进行模糊匹配（NFKC、去行尾空白、智能引号/Unicode 破折号/特殊空格归一），仅改写被触及的行
- [x] 唯一性在模糊归一空间计数；按位置排序、检测重叠、倒序应用
- [x] 空 oldText、未找到、多处匹配、重叠、无变化、访问失败的错误文案与 pi 一致（单/多编辑两种措辞）
- [x] 成功返回与 pi 一致的"替换了 N 处"信息
- [x] 范围外的 edit 被拒绝；与 write 共享同路径串行
